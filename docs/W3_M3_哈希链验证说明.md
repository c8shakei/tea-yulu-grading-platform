## 一、哈希链设计

本项目为每一次检测生成唯一的 `trace_id`（即 `detections.id`），并为其建立一条独立的哈希链，存储于 `hashchain` 表。

### 1.1 区块结构

每个区块包含以下字段：

```json
{
  "index": 0,
  "timestamp": 1693900000.123,
  "prev_hash": "0000...0000",
  "data_hash": "sha256(json(payload))",
  "hash": "sha256(index + timestamp + prev_hash + data_hash)",
  "payload": { ... }
}
```

### 1.2 计算规则

- **data_hash**：对 `payload` 按 key 排序后做 JSON 序列化，再计算 SHA-256。
  ```python
  data = json.dumps(payload, sort_keys=True, ensure_ascii=False).encode("utf-8")
  data_hash = hashlib.sha256(data).hexdigest()
  ```
- **hash**：将 `index`、`timestamp`、`prev_hash`、`data_hash` 拼接后计算 SHA-256。
  ```python
  raw = f"{index}{timestamp}{prev_hash}{data_hash}".encode("utf-8")
  block_hash = hashlib.sha256(raw).hexdigest()
  ```
- **创世区块**：`index = 0`，`prev_hash = "0" * 64`。
- **后续区块**：`index` 递增，`prev_hash` 为上一区块的 `hash`。

### 1.3 数据库表

```sql
CREATE TABLE hashchain (
    trace_id TEXT NOT NULL,
    "index" INTEGER NOT NULL,
    timestamp REAL NOT NULL,
    prev_hash TEXT NOT NULL,
    data_hash TEXT NOT NULL,
    hash TEXT NOT NULL,
    payload TEXT NOT NULL,
    PRIMARY KEY (trace_id, "index")
);
```

采用复合主键 `(trace_id, index)`，保证每条检测记录都能拥有从 `index = 0` 开始的独立链。

## 二、不可篡改验证流程

### 2.1 接口验证

调用 `GET /api/trace/{trace_id}` 时，后端执行以下步骤：

1. 从 `hashchain` 表读取该 `trace_id` 的全部区块，按 `index` 升序排列。
2. 对每个区块重新计算 `data_hash` 与 `hash`。
3. 检查相邻区块的 `prev_hash` 是否等于前一区块的 `hash`。
4. 检查创世区块的 `prev_hash` 是否等于 `"0" * 64`。
5. 检查 `index` 是否从 0 开始连续递增。
6. 返回 `valid: true/false`。

### 2.2 验证算法伪代码

```python
GENESIS_PREV_HASH = "0" * 64

for i, block in enumerate(chain):
    # 1. 校验 prev_hash 链接
    expected_prev = GENESIS_PREV_HASH if i == 0 else chain[i-1]["hash"]
    if block["prev_hash"] != expected_prev:
        return False

    # 2. 校验 data_hash
    expected_data_hash = sha256(json(payload, sort_keys=True))
    if block["data_hash"] != expected_data_hash:
        return False

    # 3. 校验 block hash
    expected_hash = sha256(f"{index}{timestamp}{prev_hash}{data_hash}")
    if block["hash"] != expected_hash:
        return False

    # 4. 校验 index 连续性
    if block["index"] != i:
        return False

return True
```

## 三、篡改检测示例

假设某条溯源链返回如下数据：

```json
{
  "trace_id": "abc123",
  "valid": true,
  "chain": [ ... ]
}
```

如果攻击者直接修改数据库或响应中的任意字段（如把 `payload.class_name` 从“特级”改为“一级”）：

1. `data_hash` 将不再与重新计算的 `sha256(payload)` 匹配。
2. 验证返回 `valid: false`。

后端自测脚本 `tests/test_backend.py` 中包含篡改模拟用例，可运行验证。

## 四、与检测流程的集成

当用户调用 `POST /api/detect` 时：

1. 后端生成 `trace_id = uuid.uuid4().hex`。
2. 调用 W2 `TeaGradeDetector` 获取 `{class_id, class_name, confidence, bbox}`。
3. 将检测结果写入 `detections` 表。
4. 以 `trace_id` 为链标识，把检测数据作为 `payload` 写入 `hashchain` 表（自动创建创世区块 + 数据区块）。
5. 更新 `detections.trace_block_index` 为数据区块的 `index`。
6. 返回检测结果与 `trace_id`。

## 五、扩展：人工复核上链

除自动检测上链外，还可通过 `POST /api/trace` 追加复核记录：

```bash
curl -X POST "http://127.0.0.1:8000/api/trace" \
  -H "Content-Type: application/json" \
  -d '{
    "trace_id": "abc123",
    "payload": {"note": "人工复核：等级无误", "operator": "质检员A"}
  }'
```

这会在同一 `trace_id` 下新增一个区块，`prev_hash` 指向该链上一区块，保证复核记录同样不可篡改。
