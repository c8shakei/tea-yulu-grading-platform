## 三、过程中遇到的异常与处理（重要，复现必读）

### 异常 1 — zip 反斜杠路径分隔符（解压阶段）
- **现象**：`unzip` 报 `appears to use backslashes as path separators`，`data.yaml` / `train/` / `val/` / `test/` 被铺平到 `/content/datasets/` 根目录而非 `/content/datasets/tea_yulu/`。
- **原因**：Drive 上的 zip 内部条目用了 `\` 作分隔符，Linux 不识别为目录。
- **临时修复（Colab）**：手动 `mkdir -p /content/datasets/tea_yulu` 并把铺平的文件 `mv` 进 `tea_yulu/`。
- **根治**：`train_detect.py` / `train_cls.py` 的 `extract_zip` 已增强，自动兼容「Windows 反斜杠 zip」「无顶层 tea_yulu/ 目录」两种情况，重跑会自动整理。

### 异常 2 — data.yaml `path: .` 被解析为 `/content`（训练阶段）
- **现象**：`FileNotFoundError: Dataset ... images not found, missing path '/content/val/images'`。
- **原因**：Ultralytics 把 `data.yaml` 中的相对 `path: .` 解析为 Colab 当前工作目录 `/content`，而非数据集目录。
- **根治**：`train_detect.py` 增加 `resolve_data_yaml`，训练前生成 `data_colab.yaml`，`path` 改写为数据集目录绝对路径后再训练。

### 异常 3 — exp_dir 路径写错导致收尾崩溃（同步阶段）
- **现象**：训练实际成功，但脚本在 val/sync 步骤抛 `FileNotFoundError: 训练未生成 best.pt`（路径 `tea_yulu_detect/yolov8n/weights/best.pt`）。
- **原因**：两脚本 `exp_dir` 误写为 `PROJECT_NAME/EXPERIMENT_NAME`，而 Ultralytics 实际把权重存到 `runs/detect/tea_yulu_detect/yolov8n` 与 `runs/classify/tea_yulu_cls/yolov8n-cls`。脚本在错误路径下找不到 best.pt → 崩溃 → **best.pt / 指标 JSON / 曲线全部未同步到 Drive**。
- **根治**：`exp_dir` 改为 `Path("runs")/<task>/PROJECT_NAME/EXPERIMENT_NAME`。
- **抢救**：权重都在 Colab 磁盘 `/content/runs/` 下，**无需重训**，用 `sync_checkpoints.py`（原恢复单元格）就地重算 test/val 指标并同步 Drive，数秒完成。

> ⚠️ 以上三个异常均已写入脚本，下次 Colab 重跑不会再触发。若 Colab 会话已断开、`/content/runs/` 被回收，则必须重训。

### 8.1 决策
组长 2026-09-04 同意在 yolov8n 基础上追加 yolov8s，观察 mAP50-95 是否显著提升（重点看「特级」0.534）。范围：**检测 + 分类对照都做**。

### 8.2 脚本变更（W1 已落地，三脚本均通过语法校验）
- `train_detect.py` / `train_cls.py`：骨干规模改由环境变量 `YOLO_MODEL_SIZE` 控制（默认 `yolov8n`，设 `yolov8s` 升级）。
  - 检测 MODEL_SIZE 直接取该值；分类 MODEL_SIZE = `{值}-cls`（yolov8n-cls / yolov8s-cls）。
  - 本地目录隔离：`runs/detect/tea_yulu_detect/<size>`、`runs/classify/tea_yulu_cls/<size>-cls`，不覆盖 n 基线。
  - batch 自适应：yolov8s 检测 16→8、分类 64→32，防 T4 OOM；可用 `YOLO_BATCH` 覆盖。
- **Drive 同步文件名全部加 size 后缀，物理隔离 yolov8n 基线**：
  - 检测：`best_detect_yolov8s.pt` / `test_metrics_yolov8s.json` / `training_curves_yolov8s.png` / `hyper_params_yolov8s.json` / `results_yolov8s.csv`
  - 分类：`best_cls_yolov8s-cls.pt` / `val_metrics_yolov8s-cls.json` / `hyper_params_cls_yolov8s-cls.json` / `results_yolov8s-cls.csv`
- `sync_checkpoints.py`：同步支持 `YOLO_MODEL_SIZE`，路径与文件名后缀与上面一致，收尾崩溃可抢救对应规模而不动另一基线。
