## 二、统一响应格式

所有接口统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

- `code = 0` 表示成功；非 0 表示失败。
- `message` 为可读说明。
- `data` 为业务数据。

## 三、接口清单

### 3.1 认证接口

| 方法 | 路径 | 说明 | 认证 |
|---|---|---|---|
| POST | `/api/auth/register` | 用户注册 | 否 |
| POST | `/api/auth/login` | 用户登录，返回 JWT | 否 |
| GET | `/api/auth/me` | 获取当前登录用户信息 | Bearer Token |
| POST | `/api/auth/logout` | 登出（客户端清除 token） | Bearer Token |

**注册 / 登录请求示例**

```bash
curl -X POST "http://127.0.0.1:8000/api/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"username":"test","password":"123456"}'

# 登录使用 OAuth2 Password 表单
curl -X POST "http://127.0.0.1:8000/api/auth/login" \
  -d "username=test&password=123456"
```

**登录成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "user_id": 1,
    "username": "test",
    "token": "eyJhbGciOiJIUzI1NiIs..."
  }
}
```

## 四、数据库 ERD

```
users ||--o{ detections : creates
detections ||--o{ hashchain : "trace_block_index"

users {
    INTEGER id PK
    TEXT username UK
    TEXT password_hash
    TEXT role
    TEXT created_at
}

detections {
    TEXT id PK
    INTEGER user_id FK
    TEXT image_hash
    INTEGER class_id
    TEXT class_name
    REAL confidence
    TEXT bbox
    INTEGER trace_block_index
    TEXT created_at
}

hashchain {
    TEXT trace_id PK
    INTEGER index PK
    REAL timestamp
    TEXT prev_hash
    TEXT data_hash
    TEXT hash
    TEXT payload
}
```

## 五、认证流程

1. 客户端调用 `POST /api/auth/login`，提交 `username` + `password`（OAuth2 表单）。
2. 服务端校验 bcrypt 密码哈希，签发 JWT（HS256，默认 24h 有效期）。
3. 客户端在后续请求 Header 中携带 `Authorization: Bearer <token>`。
4. 受保护接口（如 `/api/detections`）解析 JWT 获取 `user_id`，完成权限过滤。

## 六、环境变量

| 变量 | 说明 | 默认值 |
|---|---|---|
| `TEA_JWT_SECRET` | JWT 签名密钥 | `dev-secret-change-me-in-production` |
| `TEA_JWT_EXPIRE_HOURS` | Token 有效期（小时） | `24` |
| `TEA_DB_PATH` | SQLite 数据库文件路径 | `data/tea_yulu.db` |
| `TEA_MAX_UPLOAD_SIZE` | 上传图片大小上限（字节） | `10485760`（10 MB） |

生产环境务必替换 `TEA_JWT_SECRET`。
